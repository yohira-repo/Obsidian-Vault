# claude_daily_log

各リポジトリの `conversations.md` を収集し、Obsidian Vault へ反映する。

- `00_Claude/projects/<プロジェクト>.md` … 全履歴のミラー（時系列順）
- `01_Daily/YYYY-MM-DD.md` … **プロジェクトごとに1行**の一覧（管理ブロック内のみ）

Daily の管理ブロックはプロジェクト単位の1リストだけで、各行にそのプロジェクトの
**対象日以前で最新の記録**の日付とリンクが入る。朝に開けば前日以前の最新が並び、
その日のセッションで記録ができればその行が当日日付に変わる。

```markdown
## Claude作業ログ

<!-- claude-log:start -->
- **alphasystem** — 2026-09-03 [[00_Claude/projects/alphasystem#2026-09-03 タイトル|タイトル]]
- **alphacdk** — 2026-08-01 [[…|…]]
- **alphadb** — 記録なし

- **coop** — 記録なし
- **coopinf** — 2026-09-06 [[…|…]]
<!-- claude-log:end -->
```

並び順は alpha グループ → 空行 → coop グループ → 空行 → その他。各グループの先頭は
傘プロジェクト（`alphasystem` / `coop`）で固定し、続いてそのサブソース、記録のある
プロジェクト（日付降順）、記録なし（名前昇順）の順。

**Daily ノートはツールから新規作成しない。** 利用者が毎朝テンプレートから作る運用を
壊さないため、ノートが無ければ何もせず `daily_missing` として報告する。

## 使い方

    # ローカルのみを走査して Daily を更新（1 秒未満）
    python3 00_Claude/scripts/claude_daily_log/cli.py sync --report

    # GitHub と同期してから更新（未 clone プロジェクトの clone も行う。10 秒程度）
    python3 00_Claude/scripts/claude_daily_log/cli.py auto --force-fetch --report

    # 過去日をやり直す
    python3 00_Claude/scripts/claude_daily_log/cli.py sync --date 2026-09-01 --report

Claude Code のセッション終了時には SessionEnd hook（`~/.claude/settings.json`）が
`auto` をバックグラウンド起動する。前回 fetch から 30 分以上経っていれば GitHub 同期も行う。
手動実行はスラッシュコマンド `/daily-sync`。

## 対象の決め方

- 対象プロジェクトは `~/git/alphasystem/CLAUDE.md` と `~/git/coop/CLAUDE.md` の構成テーブルから決まる
  （相対フォルダーが `../` の行のみ。`./` 始まりは配下ディレクトリなので対象外）。
- `conversations.md` はリポジトリ内の任意の深さを探索する（`docs/` 配下、サブプロジェクト配下も対象）。
  ソース識別子はパスから `docs` を除いて作る（`alphabsmail/docs/conversations.md` → `alphasystem/alphabsmail`）。
- ローカル作業ツリー（未 commit 分を含む）とリモート追跡ブランチ全部を見て、同じ見出しはローカルを優先する。

## 見出しの扱い

| 書き方 | 結果 |
| - | - |
| `## 2026-09-06 タイトル` | そのまま当日分 |
| `## 2026-09-06: タイトル` | 同上 |
| `## 2026-09-06 — タイトル` | 同上 |
| `## 2026-08-28〜31 タイトル` | **終了日**（2026-08-31）の分として扱う |
| `## タイトル`（日付なし） | 取り込まない。`/daily-sync` の警告に件数が出る |

見出しの検出は ```` ``` ```` / `~~~` のフェンスコードブロックを認識する。フェンス内に
`## ` で始まる行（コメントの例示など）があっても見出しとしては扱わず、フェンスごと本文に残す。

同じ日付・同じタイトル（サニタイズ後の文字列で比較）のセクションが複数あれば重複排除する。
優先順位はローカル作業ツリー優先・コミット日時が新しい方優先で、それも同点なら
**ファイル内で後に出現した方**を残す（先に出た方を無条件に残す旧実装は変更済み）。

## ミラー（00_Claude/projects/*.md）は全履歴

収集は日付で絞り込まない（`sources.collect_entries` の `target_date` は省略可、
省略時は全期間）。ミラーノートには見つかった全セクションを反映し、**日付の昇順
（チェックロジカル順）で並べる**。既存ファイルに新しい日付のセクションしか
無い状態で過去日のセクションが見つかった場合は、それより前（ファイル内で上）に
挿入する。同じ日付の既存セクションがある場合は、その後ろに挿入する。
手書きで加筆した箇所（管理対象セクション外）は変更しない。

## Daily は「この日の作業」と「各プロジェクトの最新」の2段構成

```markdown
## Claude作業ログ
<!-- claude-log:start -->
### この日の作業
- **coopinf** — [[00_Claude/projects/coopinf#2026-09-06 タイトル|タイトル]]

### 各プロジェクトの最新
- **alphasystem** — 2026-09-03 [[00_Claude/projects/alphasystem#2026-09-03 タイトル|タイトル]]
- **alphasystem/alphabsmail** — 2026-08-12 [[00_Claude/projects/alphasystem-alphabsmail#2026-08-12 タイトル|タイトル]]
- **alphacdk** — 記録なし

- **coop** — 記録なし
- **coopinf** — 2026-09-06 [[00_Claude/projects/coopinf#2026-09-06 タイトル|タイトル]]
- **coopbatch** — 2026-09-02 [[00_Claude/projects/coopbatch#2026-09-02 タイトル|タイトル]]
- **coopcdeweb** — 記録なし
<!-- claude-log:end -->
```

- **この日の作業**: 対象日のエントリのみ。
  対象日の該当が0件なら `- （この日の記録はありません）` の1行になる（この場合はグループ化しない）。
- **各プロジェクトの最新**: **対象日が実際の今日（ローカル日付）と一致するときだけ**
  出力する。`--date` で過去日を指定した場合はこのサブセクション自体を丸ごと省略する
  （過去の Daily に未来の情報を持ち込まないため）。
  - 対象は `~/git/alphasystem/CLAUDE.md` と `~/git/coop/CLAUDE.md` の構成テーブルに
    載っている**全プロジェクト**（未 clone のものも含む。2026-09-06 時点で16件）。
  - 記録が1件でもあるプロジェクトは、そのプロジェクトが持つ**ソース単位**で1行ずつ出す
    （例: `alphasystem` と `alphasystem/alphabsmail` は別行）。1件も記録が無い
    プロジェクトは `- **<名前>** — 記録なし` の1行。

### システム単位のグループ化（両サブセクション共通）

  `alpha` 始まり／`coop` 始まり／それ以外の3グループに分けて描画し、
  グループ間には空行を1行挟む（1件も無いグループは区切りの空行ごと丸ごと省略）。
  グループ内の順序は次の4段階。

  1. 傘プロジェクト（alpha グループは `alphasystem`、coop グループは `coop`）が常に先頭。
     記録が無くても `- **alphasystem** — 記録なし` のように先頭に出る。
  2. 傘プロジェクトのサブソース（`alphasystem/...` / `coop/...`）を id 昇順で。
  3. 残りの記録ありエントリを日付降順（同日は id 昇順）で。
  4. 記録なしエントリをプロジェクト名昇順で。

  3つ目の「どちらにも一致しない」グループには傘プロジェクトの概念が無いため、
  3・4段階（記録あり→記録なし）のみで並べる（2026-09-06 時点では該当プロジェクト無し）。

## 注意

- Daily ノートの更新対象は `<!-- claude-log:start -->` 〜 `<!-- claude-log:end -->` の間だけ。手書き部分は変更しない。
- Daily ノートが存在しない日は何も作らない（`daily_missing`）。
- `--date` で過去日を再生成しても、その日より後の記録は出さない（as-of 表示）。
  マーカーは前後の空白を無視して認識する（末尾に空白が付いていても正常なマーカーとして扱う）。
- マーカーが片方だけ・順序が逆・重複している場合は、**ファイルを一切書き換えずに警告**を出す（手動で直すこと）。
  警告メッセージは「開始マーカー N 個 / 終了マーカー N 個」という個数だけでなく、
  順序が逆なのか・どちらかが欠落しているのか・重複しているのかを名指しする。
- **走査そのものが失敗した場合（`CLAUDE.md` が1つも読めない・対象プロジェクトが1つも clone
  されていない・clone 済みプロジェクトすべてで収集が失敗した）は、Daily ノートを一切書き換えない。**
  「対象日の該当が0件」（正常に走査できたが今日は何もなかった）とは区別しており、後者は従来通り
  管理ブロックを空にする。前者は警告のみを出し、既存の内容をそのまま残す
  （`~/git` が無い環境や、`CLAUDE.md` 追加前のブランチをチェックアウトした場合などに、
  既存の Daily ノートが空の管理ブロックへ静かに書き換えられてしまう事故を防ぐため）。
- Daily・ミラーの書き込みはアトミック（同じディレクトリに一時ファイルを書いてから
  `os.replace()` で置き換える）。SessionEnd hook 実行中にマシンが強制終了しても、
  手書きファイルが空・中途半端な状態になることはない。
- `--date` は `YYYY-MM-DD` 形式かどうかを検証する。不正な値（`not-a-date` やパストラバーサル
  を狙った `../../foo` 等）が渡された場合は、警告を出して何も書き込まずに終了コード 0 で終わる。
- 常に終了コード 0 で終わる。失敗は警告としてログ（`~/.claude/logs/claude_daily_log.log`）に残る。
- `fetch` の失敗（オフライン・git エラー等）は sync 側の処理を止めない。fetch 失敗は
  警告として記録したうえで、必ず sync（ローカル走査・Daily/ミラー更新）まで実行する。
- fetch 成功から起算する30分クロック（`~/.claude/cache/claude_daily_log.fetch_stamp`）は、
  **fetch/clone が1件も成功しなかった場合は更新しない**。オフラインのまま次回リトライが
  30分ブロックされる、という事故を防ぐため。
- 複数セッションが同時に終了しても排他制御される。POSIX（macOS/Linux）では `fcntl.flock`
  （`~/.claude/cache/claude_daily_log.lock`）。ロックが競合した場合は短い間隔で数回
  （合計 約2秒）リトライしてから諦める。取得できなければ静かに終了コード 0 で終わる
  （Daily は毎回全再生成なので、取りこぼしは次回実行で回復する）。

### Windows について

- `import fcntl` はガード付き（`try/except ImportError`）にしてあるので、Windows でも
  モジュールの読み込み自体は失敗しない。
- fcntl が無い環境では、ロックは `O_CREAT|O_EXCL` によるロックファイル方式にフォールバックする
  （多重起動の抑止という目的は満たすが、POSIX の `flock` とは実装が異なる）。異常終了で
  ロックファイルが残った場合に備え、6時間より古いロックファイルは残留とみなして削除し
  再取得を試みる。
- **Windows での動作は自動テストで検証していない**（このリポジトリの CI・テストスイートは
  POSIX 上でのみ動く）。fcntl 非対応環境向けのフォールバックはユニットテストで
  `cli.fcntl = None` に差し替えて検証しているのみで、実機の Windows での動作確認は未実施。
  ファイルパス操作・`os.replace()` によるアトミック書き込みなど、他の部分は標準ライブラリの
  クロスプラットフォーム API のみを使っており、動作すると考えている。

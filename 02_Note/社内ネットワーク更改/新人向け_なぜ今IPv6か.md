# なぜ今IPv6か ― 本件の「罠①」を教材に（新人向け1枚ノート）

作成：2026-09-15 ／ 社内ネットワーク更改（フレッツ光クロス＋OCNバーチャルコネクト）の実作業を教材化。

---

## 1. 30年の答え合わせ

- 「IPv4は枯渇する」と言われ続けて30年。**枯渇は来なかったのではなく、"見えない形で起きた"**。
- NAT/NAPT（マスカレード）と通信事業者のCGN（NAT444）が、**1つのグローバルIPv4を大勢で共有**し、枯渇をエンドユーザーから隠した。
- だから現場はIPv4だけで長年やってこられた。**それは当時の正解。**

## 2. しかし土台は反転済み

今回の回線は **MAP-E＝IPv4 over IPv6**。

```
   [ 従来 ]  IPv4 が主 ─ IPv6 は無効化してもいい添え物
   [ 現在 ]  IPv6 が土台（トランスポート） ─ その上に IPv4 が"客"として乗る
```

- **アクセス網（WAN側）の主従はもう逆転している。** IPv6が先に正しく張れないと、IPv4は1パケットも通らない。

## 3. 実話：本件の「罠①」

> **IPv6取得方式を DHCPv6-PD にすると、IPv6は通るのにIPv4が全く通らない。**
> （正解：XG-200KI（HGW）配下は例外で **RA方式**。`ipv6 lan2 address ra-prefix@lan2::<IF_ID>/64`）

- 回線ランプは正常、IPv6は疎通、なのにWebが開かない——**原因はIPv6の取得方式**だった。
- これは「IPv6が土台になった」ことの動かぬ証拠。座学100回より、この1件が効く。

補足の証拠：**固定IP1は全ポート使えるが、通常のMAP-Eはポート制限**がある。
＝1つのグローバルIPv4を**ポート単位で複数世帯に分割**して配っている。枯渇は現場のすぐ内側まで来ている。

## 4. とはいえIPv4はまだ死なない（バランス）

- **企業LAN・AWSのVPCサブネットは当面IPv4**。本件の社内VLAN（10/20/30）も全部IPv4で設計した。
- **LAN内・クラウド内はIPv4が今後10年単位で残る。** サーバでIPv4を無効化しない運用は今も正解。
- 変わったのは**"境界（WAN/アクセス網）"だけ**。そこがIPv6主導になった。
- 現実解は **デュアルスタック**（IPv4とIPv6が層として共存）。「どちらか」ではない。

## 5. 現在地（数字）

- Googleアクセスの約 **40〜45%がIPv6**（モバイル中心に伸長、日本も増加）。
- **スマホのモバイル回線はIPv6が既定・多数派**。Google/Meta/Netflix/AWS等の主要サービスは全てデュアルスタック。
- 固定回線もIPoE（IPv6）が実質標準の入口に。**PPPoEは輻輳する"遅い方"**という逆転も。

## 6. 新人に伝える最小セット

1. **アクセス網はIPv6が土台**になった。IPv4はその上を通る（IPoE / MAP-E / DS-Lite）。→ 罠①が実例。
2. **LAN・クラウド内は当分IPv4**。だからデュアルスタックが現実。
3. **NATは枯渇対策であってセキュリティではない**。IPv6ではグローバルが端末まで届きうる → フィルタ設計が本番。
4. IPv6の最低限の作法：**`/64` が基本単位**、**SLAAC/RA** と **DHCPv6-PD** の違い（＝今回ハマった所）、アドレスは"設定する"から"配られる"へ。

## 7. ひとことで

> **「IPv6は名前だけ知っていればOK」は、もう新人には危険。**
> ただし「IPv4を捨てろ」でもない。**境界はIPv6、内側はIPv4——層で共存**、が現在地。

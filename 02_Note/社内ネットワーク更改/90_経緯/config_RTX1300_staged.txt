# ①  事前投入ブロック（開通前・固定IP値なしで投入可）

# ---- ①-0 管理者モードへ（必須・最初に1回）----
#   RTXは通常モード(>)では設定コマンド不可（"Invalid command name" / "Administrator use only"）。
#   まず管理者モードへ入る:
#     administrator          ← 入力
#     Password:              ← 現在の管理者PW。工場出荷時は空なので Enter のみ（設定済みならその値）
#   プロンプトが > から # に変われば管理者モード。以降のコマンドは全て # で投入する。
administrator
# （↑ 実行後、Password: で 現在の管理者パスワードを入力／未設定なら Enter のみ）

# ---- ①-A 基本設定 ----
console character ascii
console lines infinity
# ★ RTX1300はユーザー名方式。無名の "login password" は非対応（"コマンド名を確認してください"）。
#   - ログイン用ユーザー：初期ユーザー admin（初回に admin/admin から変更済み）を使用。
#     追加ユーザーが必要な場合のみ（対話入力）:
#       login user <ユーザー名>            → New_Password: <LOGIN_PASS> → 確認
#       user attribute <ユーザー名> administrator=2   ← 管理権限も与えるなら
#   - 昇格(管理者)パスワード（対話入力）:
#       administrator password  → Old_Password:(現PW／初期は空=Enter) → New_Password: <ADMIN_PASS> → 確認
#   ※ PWは非表示。login/administrator とも同じ行にPWは書けない（encrypted指定なら1行可）。
timezone +09:00
# 確認: プロンプト表示・timezone反映（show environment / show config）

# ---- ①-B インターフェース（LAN1 保守 / LAN3 タグVLAN）----
#   ※ LAN2(WAN)は固定IP値が要るので②で投入する
ip lan1 address 192.168.200.1/24
vlan lan3/1 802.1q vid=10
vlan lan3/2 802.1q vid=20
vlan lan3/3 802.1q vid=30
ip lan3/1 address 192.168.128.1/24
ip lan3/2 address 192.168.64.1/24
ip lan3/3 address 192.168.192.1/24
# 確認: show ip interface で lan1/lan3 各アドレス。保守PCから 192.168.200.1 へ ping

# ---- ①-C DNS ----
# ★ "dhcp lan2" は使わない（HGW参照による名前解決失敗の回避）
#   ※ 名前解決の“実際の成否”は②でトンネルが通ってから（上流DNSへ到達できるのは②後）
dns server 210.145.254.170 125.170.93.234 8.8.8.8 1.1.1.1
dns service recursive

# ---- ①-D DHCP ----
dhcp service server
dhcp server rfc2131 compliant except remain-silent
dhcp scope 10 192.168.128.100-192.168.128.199/24 gateway 192.168.128.1 expire 12
dhcp scope option 10 dns=210.145.254.170,125.170.93.234,8.8.8.8,1.1.1.1
dhcp scope 20 192.168.64.100-192.168.64.199/24 gateway 192.168.64.1 expire 12
dhcp scope option 20 dns=210.145.254.170,125.170.93.234,8.8.8.8,1.1.1.1
dhcp scope 30 192.168.192.100-192.168.192.199/24 gateway 192.168.192.1 expire 4
dhcp scope option 30 dns=210.145.254.170,125.170.93.234,8.8.8.8,1.1.1.1
dhcp scope 40 192.168.200.100-192.168.200.199/24 gateway 192.168.200.1 expire 12
# DHCP予約(RDP/SSH対象PC)は MAC判明後（VPN着手時＝優先度低）に追加する:
#   dhcp scope bind 10 192.168.128.101 <MAC_01>
#   dhcp scope bind 10 192.168.128.102 <MAC_02>
#   dhcp scope bind 20 192.168.64.101  <MAC_11>
#   dhcp scope bind 20 192.168.64.102  <MAC_12>
# 確認: 各VLANのPCで正しいレンジからIP取得（ipconfig）。各GWへ ping（.128.1/.64.1/.192.1）

# ############################################################################
# ②  開通当日ブロック（OCN固定IP設定情報の到着後に投入）★方式＝map-e＋アドレス解決Lua
#     開通情報の値を置換：
#       <GLOBAL_IP> = お客さまネットワークアドレス(IPv4)  ※NAT外側はmap-eで自動。値は§8/§10で使用
#       <AR_URL>    = アドレス解決システム FQDN URL
#       <AR_ID>     = アドレス解決システム 認証用共通ID
#       <AR_PASS>   = アドレス解決システム 認証用共通パスワード
#       <AR_HOST>   = アドレス解決用ホスト名
#       <BR_IPV6>   = BR IPv6アドレス（確認用。明示指定要否は公式固定IP例で確認）
#     ★ 当日はここ（②）だけ順に投入すれば内部設定(①)の上にインターネットが乗る。
# ############################################################################

# ---- ②-G LAN2：WAN（HGW配下＝RA方式でIPv6取得）----
# ★ dhcp-prefix@(PD) にしない。map-e方式でIF_ID直書きもしない
ipv6 lan2 address ra-prefix@lan2::1/64
ipv6 lan2 dhcp service client ir=on
# 確認: show status lan2 でリンクアップ / show ipv6 address で LAN2 にグローバルIPv6

# ---- ②-H map-eトンネル・NAT・デフォルト経路 ----
tunnel select 1
 tunnel encapsulation map-e
 tunnel map-e type ocn
 ip tunnel mtu 1460
 ip tunnel tcp mss limit auto
 ip tunnel nat descriptor 1
 tunnel enable 1
ip route default gateway tunnel 1
nat descriptor type 1 masquerade
nat descriptor address outer 1 map-e
nat descriptor address inner 1 auto

# ---- ②-H2 アドレス解決システムへの登録（OCN公式Luaを使用）----
#   ocn_address_notification.lua（YAMAHA rtpro公式）を emfs:/ に配置し、冒頭変数を設定：
#     SERVER_URL=<AR_URL> / USERNAME=<AR_ID> / PASSWORD=<AR_PASS> / HOSTNAME=<AR_HOST> / IPv6_IF="LAN2"
schedule at 1 startup * lua emfs:/ocn_address_notification.lua
# ★要検証：BR(<BR_IPV6>)明示指定要否 / HGW配下(RA)でのmap-e成立 / ipv6 lan2 行 → 公式固定IP例で最終確認
# 確認: ping 8.8.8.8（IPv4到達）/ nslookup・ping www.yahoo.co.jp（名前解決）
#       show nat descriptor address 1 / show ip route

# ---- ②-I WAN側フィルタをトンネル1へ適用 ----

# 確認: 内部PCからインターネット到達が維持（フィルタ適用後の疎通）

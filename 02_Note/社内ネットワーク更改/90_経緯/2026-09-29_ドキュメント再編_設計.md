# 社内ネットワーク更改ドキュメント 再編設計

作成：2026-09-29 ／ 対象：`02_Note/社内ネットワーク更改/` 配下

---

## 1. 背景と目的

構築完了（2026-09-14）までに20ファイルが蓄積し、**保守に必要な情報・残タスク・構築時の経緯が混在**している。障害時に必要な文書へ辿り着けず、他者への引き継ぎもできない状態。

### 目的（優先順）

1. **障害時に最短で辿り着ける** — 症状から開くべき文書が一意に決まる
2. **他者へ引き継げる** — 前提知識のない担当者が読んで運用できる

副次的に残タスクの可視化とアーカイブ整理も行うが、上記2つを損なう変更はしない。

---

## 2. 設計原則

| 原則 | 内容 |
|---|---|
| **情報の出どころは1つ** | 同じ事実を2か所に書かない。片方は必ずリンクで参照する。**これを破ると片方だけ更新されて食い違う** |
| **既存を正とする** | 既に実体のある文書は書き起こさずリネーム・昇格させる |
| **読者で分ける** | 「運用する人」「やり残しを見る人」「なぜそうしたか遡る人」でフォルダを分ける |
| **リンクを壊さない** | ファイル移動はすべて Obsidian CLI 経由。シェルの `mv` は使わない |

## 5. 各文書の仕様

### 5-1. `00_はじめに.md`（新規）

**読者**：初めてこのフォルダを開いた人。**分量**：A4一枚。

- このネットワークは何か（3行）
- **症状 → 開く文書 の対応表**（例：「ネットに繋がらない」→ `13_障害対応`）
- 現在の状態（2026-09-14 時点で全VLAN正常稼働、固定IP `124.100.212.73`）
- フォルダの意味（10=保守／20=残タスク／90=経緯）
- 更新ルール（設定を変えたら `11_構成台帳` を直す／決定は `conversations.md` へ）

### 5-2. `10_保守/11_構成台帳.md`

**`社内LANネットワーク設定.md` をリネームして昇格。** 新規に書き起こさない（同じ情報の出どころを2つにしないため）。

追加・更新する内容：

1. **冒頭に「現況サマリ」表を新設** — 機器・型番・管理IP・管理画面URL（**http/https の別を明記**）・VLAN・ゲートウェイ・グローバルIP
2. **実機確定値への更新** — Port3＝作業PC接続ポート／Port5のVLAN20/30は**タグ**／`httpd host lan1 lan3/1`／RTX `lan3/2` のフィルタ修正（`2099`・`dynamic 3030/3031`）
3. **`00_サマリ.md` §3〜§5 の統合** — 確定構成・IP設計・アクセス制御
4. **認証情報の「所在」** — パスワードの値は書かず、**どこに保管してあるか**を記載
5. **設定バックアップの保管場所と取得時点**

### 5-3. `10_保守/12_日常運用.md`（新規）

**読者**：運用担当者。**位置づけ**：「壊れてはいないが何かを変えたいとき」の作業手順集。

収録する作業：

- PC・端末を1台追加する（設置場所→VLAN→挿すHUB→DHCPで自動取得→確認方法）
- 固定IPを払い出す（`.2`〜`.99` を使う理由＝`.100` 以降はDHCP配布範囲）
- 複合機など固定IP機器を入れ替える
- SSIDのパスワードを変更する（**全端末が切断される**ため実施タイミングの注意）
- 設定バックアップを取る（XS508TM＝メンテナンス>エクスポート／RTX＝`save`）
- ファームウェアを更新する（事前バックアップ必須）
- **停電・ブレーカー落ちから復旧する**（起動順序：ONU → XG-200KI → RTX1300 → XS508TM → AP。順序を誤るとRTXがIPv6を取得できずIPv4が通らない）
- 管理画面へのアクセス方法一覧（IP・http/https の別・アクセス元の制限）

### 5-4. `10_保守/13_障害対応.md`（新規・既存の集約）

**読者**：障害発生時の担当者。**構成**：

1. **切り分けの定石**（新規）— どこから ping するか／スイッチのアドレステーブルの見方／**設定変更後は1分待ってから判定する**／Macを使った直結テスト
2. **症状別の切り分け** — `切替・障害切り分け手順.md` §5 の8項目
3. **確認コマンド集** — 同 §6（`show status dhcp` 等、実機で検証済みの正しいコマンド名）
4. **既知トラブル事例** — `config_XS508TM.md` §8 の実録3件（Port1のVLANメンバーシップ不整合／Port5の`U`重複／RTX `lan3/2` の out フィルタ）
5. **踏んではいけない罠** — `00_サマリ.md` §6

### 5-5. `20_残タスク/21_残タスク一覧.md`（新規）

`00_サマリ.md` §9 を移設。A〜D／後日検討／事後対応の区分を維持し、各項目に**優先度と実施時期の目安**を付与する。

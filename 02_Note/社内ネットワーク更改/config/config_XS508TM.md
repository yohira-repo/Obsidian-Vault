# NETGEAR XS508TM 設定手順書（コアスイッチ）

XS508TM は **8ポート10G/マルチギガ + SFP+×2 のスマートスイッチ**です。テキストconfigではなく**ローカルWeb管理画面**で設定します（NETGEAR Insightは使用しません）。

> **管理画面は HTTP のみ**（HTTPS非対応）。ブラウザにIPだけ入力すると自動で `https://` を試して**繋がらない**ため、必ず **`http://192.168.128.2/`** と明示してください（2026-09-14にハマりました）。

- 設計根拠：[[社内LANネットワーク設定]]（XS508TM ポート使用図、3-1 セグメント一覧）
- 関連：[[config_RTX1300]] / [[config_XG-200KI]]

---

## 0. 設定方針

**RTX1300とはタグVLAN（802.1Q）で接続し、下位のエリアスイッチへはアンタグで落とす。** VLAN IDは **10／20／30** を使用し、既定VLAN（VID 1）は業務に使用しません。

**本機は L2スイッチとして使用します。** VLANにIPアドレスを持たせません（ゲートウェイはRTX1300側の `ip lan3/x address`）。左メニューの **「ルーティング」は触らないでください**。スイッチにVLANインターフェイスIPを持たせると、RTX1300のVLAN間フィルタを迂回する経路ができ、分離設計が崩れます。

## 0-1. GUI操作パス（実機準拠・2026-09-14 確認）

設定項目が複数画面に分かれており、探すのに時間がかかります。**実機で確認した場所**は次のとおりです。

| やりたいこと | 場所 | 操作 |
| --- | --- | --- |
| **VLANの作成／名称** | スイッチング > VLAN > VLAN > **VLAN設定（基本）** | VLAN IDと名称を入力 |
| **ポートのVLANメンバーシップ（T/U）** | 同上 **VLAN設定（基本）** | **VLAN IDを1つ選び**、ポート図のセルをクリックして `U`→`T`→空白 と切替 → **適用**。**VLANごとに繰り返す**（ポート単位の一括画面ではない） |
| **PVID** | スイッチング > VLAN > VLAN > **VLAN設定（高度）> PVID設定** | 行のチェックボックスをON（複数可）→ 右上 **「編集」** → PVID入力 → 保存 |
| **ポートの有効／無効** | スイッチング > **ポート** > **「ポート設定」タブ** | 対象をチェック → 編集 → **`管理者ステータス`** を「無効」 |
| **管理IP** | システム > 管理 配下のIP設定 | **IP割当モードを Static に切替**してから入力（DHCPのままだと戻る） |
| **管理VLAN** | システム > 管理 配下のIP/インターフェイス設定 | VLAN画面側ではない |
| **MACアドレステーブル** | スイッチング > **アドレステーブル** | 検索は部分一致（例 `f4:d5:80`）。**既定300秒で消える**ので直前に通信を発生させる |
| **ping / traceroute** | メンテナンス > **トラブルシューティング** | この2つのみ |
| **設定のバックアップ** | メンテナンス > **エクスポート** | ファイルとしてPCへ保存 |
| **ファームウェア更新** | メンテナンス > アップデート | |

### ★ 落とし穴

- **「保存」ボタンは存在しません。** メンテナンス配下は「リセット／エクスポート／アップデート／ファイル管理／トラブルシューティング／登録キー」のみで、**適用（Apply）した時点で起動時設定にも書かれます**。本書で「適用」と書いてある箇所は、それ以上の保存操作は不要です。
- **スイッチング > ポート を開くと既定で「LLDP」タブ**が表示されます。そこにも `管理者ステータス` がありますが**これはLLDPの送受信設定**で、ポートの有効/無効ではありません。**一番右の「ポート設定」タブ**を使ってください。
- **ファイル管理／エクスポートは設定の保存ではなくバックアップ機能**です。

### インターフェース名とポート番号の対応

テーブル形式の画面では内部名（`xg1`〜）、ポート図では本体印字（`1`〜）が使われます。

| テーブル表記 | ポート図表記 | 物理ポート |
| --- | --- | --- |
| `xg1` 〜 `xg8` | `1` 〜 `8` | 前面RJ-45 1〜8 |
| `xg9` | `9F` | SFP+ 1 |
| `xg10` | `10F` | SFP+ 2 |
| `l1` 〜 `l4` | — | **LAGの論理IF（枠のみ）。本構成では使用しないため一切設定しない** |

## 2. VLAN定義

| VLAN ID | 名称      | 用途      | ネットワーク             |
| ------: | ------- | ------- | ------------------ |
|      10 | Office  | 営業・総務管理 | `192.168.128.0/24` |

|      30 | Guest   | ゲスト専用   | `192.168.192.0/24` |

>

### 3-2. 設定時の注意（★ロックアウト回避）

> **PVID とは**：そのポートに**タグ無し**で入った通信を「どのVLANに入れるか」を決める番号（値はVLAN ID）。PCは通常タグ無し送信なので、**管理PCのポートは PVID=管理VLAN(10) かつ VLAN10 アンタグ**でないと管理IPに届かない。

> [!warning] ★★ 最重要ルール3つ（2026-09-11〜14に全部踏みました）
> 1. **アンタグ（`U`）にできるVLANは、1ポートにつき1つだけ。** Port5を VLAN10/20/30 すべて `U` にしていたため、**無線のVLAN20/30が成立しませんでした**。トランクは「ネイティブ1つだけ `U`、残りは `T`」。
> 2. **設定を変更したら、テストの前に30秒〜1分待つ。** 適用直後はスイッチ内部（MACテーブル等）の再収束が終わっておらず、直っているのに「失敗」と誤判定します。**この誤判定で半日失いました。**
> 3. **管理VLANの移行では必ず一度切断される。** 1本のケーブルでは回避不能なので、**「切れる前に着地点のポートを用意しておく」**のが正解（→ §7-2）。

- **管理はアクセスポートから行い、そのポートのVLANと“管理VLAN”を常に一致させる。** 管理VLANを10へ移すのに作業ポートがVLAN10側でないと、IPを合わせても管理画面を見失う（実際に発生：2026-09-11、同日に2回）。
- **ロックアウトしない設定順（推奨）**：
  1. 管理IPを **Static** で `192.168.128.2/24`・GW `192.168.128.1` に設定（**管理VLANはこの時点では既定=1のまま**）→ 適用 → PCを `192.168.128.x` にして `http://192.168.128.2/` へ再接続
  2. VLAN **10/20/30 を作成**
  3. **作業PCのポート以外**（Port1/2/4/5/6/7/8）のメンバーシップと **PVID** を設定（3-1 の表どおり）
  4. **作業PCのポート（実機ではPort3）を「VLAN10 アンタグ＋PVID10」**にする
  5. **管理VLANを 1 → 10 へ変更**（IPは `192.168.128.2` のまま）→ **ここで必ず切断される。正常な挙動** → 作業PCがVLAN10側（手順4のポート）にいれば `http://192.168.128.2/` の再読込で復帰
- **要点**：一般には「PVIDは最後」だが、**“管理に使うポートだけは先に 管理VLAN(10) のアンタグ＋PVID10”**にしてから管理VLANを10へ動かすこと。
- **見失った時の復旧**：Resetボタン約10秒長押しで工場出荷（既定 `192.168.0.239` / 全ポートVLAN1）。PCを `192.168.0.x` にして再ログインし、上記手順でやり直す。**リセットすると管理IPの変更も消える**点に注意。
- **Port 1（RTX1300向け）のPVID**：`10`。トランクにタグなしフレームが入った場合にVLAN 10へ落ちる。
- **未使用ポート（7・8・SFP+）**：スイッチング > ポート > **ポート設定タブ**で `管理者ステータス` を**無効**（誤接続による意図しないVLAN流入を防止）。VLANメンバーからの除外は任意（無効化すれば通信は発生しない）。
- LXW-10G8 は**アンマネージドスイッチ**のため設定不要（XS508TM側でアンタグにすれば配下は単一VLAN）。

## 6. 補足：VLAN IDを 10/20/30 とした理由

VID 1 は、ほぼすべてのスイッチで**既定VLAN（ネイティブ／アンタグ）として予約**されています。これをタグ付きで流すと機種依存の挙動差が出やすく、トランクポートのPVIDが1のままだとタグなしフレームが業務VLANへ流入する余地も残ります。

10刻みとすることで、将来のVLAN追加（40, 50…）にも番号が枯れずに対応できます。

## 7. 参考：工場出荷リセットと「ロックアウトしない」再構築順

> 管理VLANを10へ移す際、管理PCの接続ポートが「VLAN10 アンタグ＋PVID10」でないと、IPを合わせても管理画面を見失う（2026-09-11に発生）。GUIに到達できなくなったらリセットして下記の順でやり直す。

### 7-1. 工場出荷リセット

1. **Resetボタンを約10秒長押し**（LEDが点滅→再起動）。
2. 既定に戻る：**管理IP `192.168.0.239`**（DHCP不成立時のフォールバック）／**全ポート VLAN1**。
3. 管理PCを **`192.168.0.100 / 255.255.255.0`** にして `http://192.168.0.239/` へ。初回ログインで管理者パスワードを設定。

### 7-2. ロックアウトしない再構築順

| 手順 | 操作 | ポイント |
|---:|---|---|
| 1 | 管理IPを **Static** `192.168.128.2/24`・GW `192.168.128.1` に設定（**管理VLANは既定=1のまま**）→ 適用 → PCを `192.168.128.100/24` にして `http://192.168.128.2/` へ再接続 | まだVLAN1で管理。ここで到達を確立 |
| 2 | **VLAN 10 / 20 / 30 を作成** | ─ |
| 3 | **作業PCのポート“以外”**のメンバーシップ＋PVIDを設定（3-1の表） | Port1=タグ10/20/30・PVID10／**Port5=VLAN10アンタグ(U)＋20/30タグ(T)・PVID10**（AP側Untagged VLAN=10に合わせる）／Port2=U20・PVID20／Port4・6=U10・PVID10／Port7〜10=無効化 |
| 4 | **作業PCのポート（実機ではPort3）を「VLAN10 アンタグ＋PVID10」**にする | **これが“着地点”。次の手順で切れたときの戻り先** |
| 5 | **管理VLANを 1 → 10 へ変更**（IPは `192.168.128.2` のまま） | **ここで必ず切断される（正常）。** 作業PCが手順4のポートにいれば `http://192.168.128.2/` の再読込で復帰。別ポートで作業していた場合はケーブルをPort3へ挿し替える |
| 6 | 疎通確認（**適用から30秒〜1分待つ**） | 直後にテストすると再収束前で誤判定する |
| 7 | **メンテナンス > エクスポートでバックアップ** | 正常動作している状態を保全。次回のロックアウト時はここから復元できる |

### 7-3. 核心

一般則は「PVIDは最後」だが、**“管理に使うポートだけは、先に 管理VLAN(10) のアンタグ＋PVID10 にしてから、管理VLANを10へ動かす”**。

**そして「切らずに移行する」ことは1本のケーブルでは原理的に不可能**です。どちらの順序でも必ず一度切れるので、**切れる前に着地点（VLAN10アンタグ＋PVID10のポート）を用意しておく**のが唯一の正解です。

> PVID＝そのポートに**タグ無し**で入った通信が所属するVLAN ID。PCは通常タグ無し送信のため、管理PCのポートは **PVID=管理VLAN(10)** が必須。

## 8. トラブルシューティング事例（2026-09-11〜14 実録）

### 8-1. 全VLANが不通／RTX1300が「未サポートパケット」を大量に破棄する

| 項目 | 内容 |
|---|---|
| **症状** | VLAN10のPC・スイッチ自身・APのいずれからもRTX（`192.168.128.1`）へ到達不能。RTXの `show status lan3` で**受信の約80%が「未サポートパケット」**。RTXの `show arp` は**カウント0** |
| **紛らわしい点** | GUI上は Port1 が `T` と**正しく表示されていた**。ケーブル交換・ファーム・RTX側の設定はいずれも**無関係**だった |
| **原因** | **Port1のVLANメンバーシップが内部的に不整合な状態**になっていた |
| **対処** | VLAN設定（基本）で **VLAN10/20/30それぞれについて、Port1を一度「非メンバー（空白）」にして適用 → 再度 `T` にして適用** |
| **注意** | **適用後30秒〜1分待ってからテスト**。直後だと直っていても失敗する |

**切り分けの決め手**：スイッチの**アドレステーブル**にRTXのMACが `VLAN10 / xg1` で載っているかを見る。載っていれば「RTX→スイッチ方向は正常」と分かり、原因を半分に絞れる。

### 8-2. 無線のVLAN20/30だけIPが取れない

| 項目 | 内容 |
|---|---|
| **症状** | Office(VLAN10)の無線は正常だが、Develop(20)・Guest(30)でIPが配布されない |
| **原因** | **Port5（AP向けトランク）が VLAN10/20/30 すべて `U`（アンタグ）**になっていた |
| **なぜダメか** | **アンタグにできるVLANは1ポートにつき1つだけ。** APが送るVLAN20/30のタグ付きフレームが正しく扱われず、スイッチからAPへもタグを付けずに返してしまう |
| **対処** | VLAN20・VLAN30 の Port5 を **`T`** に変更（VLAN10は `U` のまま） |

### 8-3. 有線・無線ともVLAN20だけIPが取れない

**スイッチ側ではなくRTX1300側が原因**でした。`ip lan3/2 secure filter out` に「RTX自身からVLAN20への送信」を許可するルールが無く、DHCPのOFFER応答が落ちていました。→ **[[config_RTX1300]] §9-4 の警告ボックス**を参照。

**見分け方**：RTXの `show arp` に **VLAN20の端末が `LAN3/2` として載っている**のに ping / DHCP だけ通らない場合は、**ARPはIPフィルタの対象外**なので「L2は正常、IPフィルタが原因」と断定できます。

### 8-4. 管理画面に繋がらない

**HTTPSで接続しようとしている**可能性が高いです。本機は **HTTP のみ**対応。ブラウザはIPだけ入力すると自動で `https://` を試すため失敗します。**`http://192.168.128.2/`** と明示してください。

> 参考：AP（BE9400）は **HTTPS** なので `https://192.168.128.3/`。**機器ごとに違う**点が混乱のもとです。

### 8-5. 切り分けの定石（次回これをやれば早い）

1. **スイッチの メンテナンス > トラブルシューティング から ping** … 上流（Port1〜RTX）か下流かを一発で分ける
2. **スイッチの アドレステーブル** … 相手のMACが期待するVLAN／ポートで学習されているか
3. **RTXの `show arp` / `show ip route` / `show status dhcp`** … L2は届いているか、経路はあるか、DHCPは配ったか
4. **PCを直結**して機器を1台ずつ除外 … MacならVLANタグ付きIFを作れば**スイッチの代役**になれる
   ```
   sudo ifconfig vlan0 create
   sudo ifconfig vlan0 vlan 10 vlandev en6
   sudo ifconfig vlan0 inet 192.168.128.60 netmask 255.255.255.0 up
   sudo ifconfig vlan0 destroy    # 後片付け
   ```
5. **変更のたびに1分待つ**

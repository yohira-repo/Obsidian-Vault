## 0. 最初に読む：切り分けの定石

焦って設定を触る前に、**この5つ**を守ってください。過去の障害対応で、これを守らなかったために余計な時間を失っています。

### ① 範囲を確認する（誰が・どこまで繋がらないか）

| 確認 | 分かること |
|---|---|
| **1台だけか、全員か** | 1台なら端末側。全員ならネットワーク側 |
| **特定のVLANだけか** | VLAN10だけ／VLAN20だけ、なら該当の経路に絞れる |
| **有線だけか、無線もか** | 無線だけならAP（`192.168.128.3`）側 |
| **社内は見えるが外に出られないのか** | 社内OK＝スイッチまでは正常。RTX1300より上流の問題 |

### ② 上流から順に ping する

```
ping 192.168.128.1     ← RTX1300（ゲートウェイ）
ping 192.168.128.2     ← XS508TM（コアスイッチ）
ping 192.168.128.3     ← BE9400（AP）
curl -I https://www.google.com
```

> **`ping 8.8.8.8` が通らないのは正常です。** RTX1300のWAN側フィルタでICMPの戻りが落ちるため（動的フィルタがICMP非対応というヤマハの仕様）。**インターネットの確認は `curl` かブラウザで**行ってください。

### ③ ARPが解決しているかを見る

```
arp -n 192.168.128.1
```

- **MACアドレスが表示される** → L2（イーサネット）は届いている。**問題はIPフィルタか上位**
- **`(incomplete)` と表示される** → **L2の段階で届いていない**。VLAN設定・結線・ポートを疑う

**この判別は非常に強力です。** ARPはIPフィルタの対象外なので、「ARPは通るのに ping が通らない」なら**フィルタが原因**と断定できます。

### ④ 設定を変えたら30秒〜1分待ってから判定する

スイッチは設定適用直後、内部の再収束（MACテーブルの更新など）が終わっていません。**直っているのに「失敗」と誤判定します。**

> 2026-09-14の障害対応で、実際にこれで半日を失いました。正しい対処をしたのに「効果なし」と判断し、ケーブル・ファームウェア・ルーターを疑って回りました。

### ⑤ 機器を1台ずつ経路から外す

原因の機器が絞れないときは、**物理的に直結**して変数を減らします。

MacならVLANタグ付きインターフェースを作れるので、**スイッチの代役**になれます。

```
sudo ifconfig vlan0 create
sudo ifconfig vlan0 vlan 10 vlandev en6
sudo ifconfig vlan0 inet 192.168.128.60 netmask 255.255.255.0 up
ping 192.168.128.1

sudo ifconfig vlan0 destroy    # 後片付け
```

RTX1300のLAN3（物理ポート10）に直結してこれが通れば、**RTX1300は正常でスイッチが原因**と確定できます。

## 1. 症状別の切り分け

### 1-1.【最頻・最優先】IPv6は通るがIPv4が通らない

| 項目 | 内容 |
|---|---|
| **症状** | `ping6` は通る／IPv6サイトは見えるが、IPv4通信が全滅 |
| **原因** | RTX1300のIPv6取得方式が **DHCPv6-PD** になっている。HGW配下ではプレフィックスを取得できず、**MAPルールが適用されない**ためトンネルが成立しない |
| **確認** | `show status ipv6 dhcp` ／ `show ipv6 address` ／ `show status tunnel 1` |
| **対処** | **RA方式へ変更**（`ipv6 lan2 address ra-prefix@lan2::1/64`）しトンネルを再確立 |

> 「IPv6は通るので回線は生きている」と誤認しやすいのが最大の罠です。**IPv4が通らない場合はまずここを見る**こと。

### 1-2. IPv4は通るがIPv6の名前解決ができない

DNS設定が自動（`dhcp lan2`）でHGWを参照し、そのサーバへの到達経路が生成されないのが原因。**パブリックDNSを直接指定**するか静的経路を追加します。

### 1-3. まったく通信できない

上から順に確認します。

1. **10G-EPON ONU の前面ランプ**（電源・光回線・認証）→ 異常なら回線/ONU側
2. **ONU → XG-200KI WAN** の結線・リンク（CAT6A）
3. XG-200KI の前面ランプ（登録・電話・ACT・電源が緑か）
4. 結線先の確認（**XG-200KI は LAN4**、**RTX1300 は LAN2**）
5. `show status lan2` でリンクアップ・速度
6. **XG-200KI に接続先設定が入っていないか**（入っていると二重ルータになる）
7. **ONU → XG-200KI → RTX1300 の順に再起動** → 5分待って再確認（→ [[12_日常運用]] の起動順序）
8. RTX1300 を再起動
9. NTT東日本 故障受付 `0120-594-202`（ONU/HGWのランプ状態を控えておく）

### 1-4. グローバルIPが契約の固定IPと違う

- **原因**：XG-200KI 側でIPv4を終端している／RTX1300のトンネル設定の投入漏れ
- **確認**：`curl https://ifconfig.io` ／ `show nat descriptor address` ／ `show config`
- **対処**：XG-200KI の接続先設定を削除、RTX1300のトンネル設定を再投入

正常時のグローバルIPは **`124.100.212.73`** です。

### 1-5. 特定のVLANだけ通信できない

**まず [[#2. 既知のトラブル事例]] を見てください。** 過去に3回、別々の原因で発生しています。

確認の順序：

1. RTX1300 LAN3 のタグVLAN設定（`show config | grep lan3` で VLAN 10/20/30 すべてあるか）
2. **XS508TM Port1 が該当VLANで `T`（タグあり）になっているか**
3. **XS508TM の下位ポートが正しいアンタグVLANになっているか**
4. **スイッチのアドレステーブル**で、相手のMACが期待するVLAN／ポートで学習されているか
5. LXW-10G8 はアンマネージドのため設定不要（＝疑う対象外）

### 1-6. VLAN間の制御が意図通りに動かない

| 症状 | 原因 | 対処 |
|---|---|---|
| VLAN10→VLAN20 の **ping だけ**通らない | **仕様**（動的フィルタはICMP非対応） | **異常ではありません。** TCPで確認（`Test-NetConnection -Port 3389`） |
| VLAN10→VLAN20 が通らない（TCPも） | `lan3/2 secure filter out` の静的 `pass`（2101）が無い／`dynamic` より後にある | 静的 `pass` を `dynamic` より**前**に配置 |
| VLAN20→VLAN10 が通ってしまう | `lan3/2 secure filter in` の拒否（2000）が無い | `in` 側の拒否ルールを確認 |
| 複合機からVLAN20へ通信できてしまう | 拒否（2100）が許可（2101）より後 | 送信元 `192.168.128.20` の拒否を**先頭**へ |
| VLAN10・20 からインターネットが通らない | `lan3/1`・`lan3/3` に `secure filter out` を設定してしまい戻りが落ちている | LAN側の `out` フィルタを外す |
| セッション状態を確認したい | － | `show ip connection summary` |

### 1-7. リモートアクセスVPNの不具合

| 症状 | 確認・対処 |
|---|---|
| VPNは接続できるが社内に届かない | `ip pp secure filter in` で到達先VLANのTCP 3389／22が許可されているか |
| 払い出しIPが指定値と違う | `pp auth username` の指定IPが `ip pp remote address pool` と**重複していないか** |
| 複数ユーザーが同時接続できない | トンネル数が不足（`pp bind tunnel1-tunnelN`） |
| RDPだけ繋がらない（pingは通る） | **Windowsファイアウォール**のRDP受信規則が「ローカルサブネットのみ」になっている |
| SSHだけ繋がらない | Linux端末の `sshd` / firewalld / ufw で `192.168.201.0/24` が未許可 |

### 1-8. AWS拠点間VPNが確立しない

- `show ipsec sa` で Phase1／Phase2 の状態を確認
- MAP-E上で **IKE（UDP 500／4500）・ESP** が通過するか
- 固定IP1は**全ポート利用可能**（ポート制限なし）と確認済み

## 2. 既知のトラブル事例

**2026-09-11〜14 に実際に発生し、解決したもの**です。同じ症状が出たらまずここを疑ってください。

### 2-1. 全VLANが不通（XS508TM Port1 のVLANメンバーシップ不整合）

| 項目 | 内容 |
|---|---|
| **症状** | VLAN10のPC・スイッチ自身・APのいずれからもRTX（`192.168.128.1`）へ到達不能。RTXの `show status lan3` で**受信の約80%が「未サポートパケット」**。`show arp` は**カウント0** |
| **紛らわしい点** | **GUI上は Port1 が `T` と正しく表示されていた**。ケーブル交換・ファームウェア・RTX側の設定はいずれも無関係だった |
| **原因** | Port1のVLANメンバーシップが**内部的に不整合**な状態になっていた |
| **対処** | VLAN設定（基本）で**VLAN10/20/30それぞれについて、Port1を一度「非メンバー（空白）」にして適用 → 再度 `T` にして適用** |
| **注意** | **適用後30秒〜1分待ってからテスト**。直後だと直っていても失敗する |

**切り分けの決め手**：スイッチのアドレステーブルにRTXのMAC（`f4:d5:80:3b:60:e0`）が `VLAN10 / xg1` で載っているかを見る。載っていれば「RTX→スイッチ方向は正常」と分かり、原因が半分に絞れる。

### 2-2. 無線のVLAN20/30だけIPが取れない（アンタグの重複）

| 項目 | 内容 |
|---|---|
| **症状** | Office(VLAN10)の無線は正常だが、Develop(20)・Guest(30)でIPが配布されない |
| **原因** | **Port5（AP向けトランク）が VLAN10/20/30 すべて `U`（アンタグ）**になっていた |
| **なぜダメか** | **アンタグにできるVLANは1ポートにつき1つだけ。** APが送るVLAN20/30のタグ付きフレームが正しく扱われず、スイッチからAPへもタグを付けずに返してしまう |
| **対処** | VLAN20・VLAN30 の Port5 を **`T`** に変更（VLAN10は `U` のまま） |

### 2-3. 有線・無線ともVLAN20だけIPが取れない（RTXの出力フィルタ）

| 項目 | 内容 |
|---|---|
| **症状** | VLAN20の端末にIPが配布されない。手動でIPを設定しても `ping 192.168.64.1` が通らず、Webも見られない |
| **原因** | `ip lan3/2 secure filter out` に**RTX自身（`192.168.64.1`）からVLAN20への送信を許可するルールが無く**、DHCPのOFFER応答・ICMP応答・インターネットからの戻りが暗黙拒否で落ちていた |
| **なぜ起きたか** | **`out` フィルタはルーター自身が送信するパケットにも適用される。** `lan3/2` は唯一 `out` フィルタを持つインターフェースだった |
| **対処** | `ip filter 2099 pass 192.168.64.1 * * * *` を `out` の先頭へ、`dynamic 3030/3031` を `in` 側へ追加（→ [[config_RTX1300]] §9-4） |

**見分け方**：RTXの `show arp` に**VLAN20の端末が `LAN3/2` として載っている**のに ping / DHCP だけ通らない場合は、**ARPはIPフィルタの対象外**なので「L2は正常、IPフィルタが原因」と断定できる。

### 2-4. 管理画面に繋がらない

**HTTPSで接続しようとしている**可能性が高いです。機器ごとに違います。

| 機器 | URL |
|---|---|
| RTX1300 | **`http://192.168.128.1/`**（HTTPのみ） |
| XS508TM | **`http://192.168.128.2/`**（HTTPのみ） |
| BE9400 | **`https://192.168.128.3/`**（HTTPS） |

ブラウザはIPだけ入力すると自動で `https://` を試すため、RTXとスイッチは失敗します。**`http://` を明示**してください。

また **RTX1300の管理画面は保守セグメントとVLAN10からのみアクセス可能**です（`httpd host lan1 lan3/1`）。VLAN20/30からは `503 Service Unavailable` が返ります。**これは意図した動作**です。

## 4. 踏んではいけない罠

設計・検証で確定した8点です。**知らずに設定すると詰みます。**

| # | 罠 | 正解 |
|--:|---|---|
| ① | **IPv6取得方式をDHCPv6-PDにする** | 光クロスの原則はPDだが、**XG-200KI配下は例外でRA方式**。PDにすると**IPv6は通るがIPv4が全く通らない** |
| ② | DNSを自動設定のままにする | `dhcp lan2` でHGWを参照し名前解決に失敗。**パブリックDNSを直接指定** |
| ③ | **VLAN IDに 1 を使う** | VID 1 は既定VLANとして予約。**VID 10／20／30 を使用** |
| ④ | 動的フィルタでICMPを許可しようとする | **ICMPは指定不可**。VLAN間の ping は通らない。**疎通確認はTCPで** |
| ⑤ | 片方向許可を静的フィルタだけで組む | **戻りパケットが落ちる**。宛先側IFの `in` で相手発を拒否し、`out` に静的 `pass` ＋ `dynamic` |
| ⑥ | LAN側インターフェースに `secure filter out` を置く | インターネットやVLAN20からの**戻りパケットまで落ちる**。`lan3/1`・`lan3/3`・`lan1` には設定しない。**`lan3/2` に置く場合はルーター自身の送信許可（2099）が必須**（→ 2-3） |
| ⑦ | `ip pp remote address pool` と固定指定IPを併用 | プール側から別アドレスが払い出され**フィルタが効かなくなる**。全ユーザー固定指定 |
| ⑧ | RTX1200/1210の記事どおり `vlan port mapping` を使う | **RTX1300では使えない**。`lan flexible-port` で代替（変更時は `save`＋`restart`） |

**フィルタは適用順序が結果を決めます。** 複合機→VLAN20の拒否（2100）は許可（2101）より前に置く必要があります。

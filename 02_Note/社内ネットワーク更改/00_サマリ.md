## 5. アクセス制御（確定）

| 通信方向 | 可否 |
|---|:--:|
| VLAN10 → VLAN20 | **許可**（動的フィルタで片方向） |
| VLAN20 → VLAN10 | **拒否**（例外なし） |
| 複合機 `192.168.128.20` → VLAN20 | **拒否**（VLAN10→20許可の例外） |
| VLAN30 → VLAN10・20・保守・AWS | **拒否** |
| VLAN30 → インターネット | 許可 |
| VLAN10 → AWS `10.0.3.0/24` | 許可（**事後対応**） |
| VLAN20・30 → AWS | 拒否 |
| 保守 → VLAN10・20 | 許可（逆方向は拒否） |
| インターネット → 社内（着信） | **拒否**（インバウンド公開なし） |

## 6. 踏んではいけない罠（最重要）

この8点は調査・検証で確定した内容です。**知らずに設定すると当日詰みます。**

| # | 罠 | 正解 |
|---:|---|---|
| ① | **IPv6取得方式をDHCPv6-PDにする** | 光クロスの原則はPDだが、**XG-100NE配下は例外でRA方式**。`ipv6 lan2 address ra-prefix@lan2::<IF_ID>/64`。PDにすると**IPv6は通るがIPv4が全く通らない**（回線が生きているように見えるため切り分けが難航） |
| ② | DNSを自動設定のままにする | `dhcp lan2` でHGWを参照し到達経路が生成されず名前解決に失敗。**パブリックDNSを直接指定** |
| ③ | **VLAN IDに 1 を使う** | VID 1 は既定VLAN（ネイティブ／アンタグ）として予約。**VID 10／20／30 を使用** |
| ④ | 動的フィルタでICMPを許可しようとする | **ICMPは指定不可**。VLAN間の ping は通らない。**疎通確認はTCPで**（`Test-NetConnection -Port 3389`） |
| ⑤ | 片方向許可を静的フィルタだけで組む | **戻りパケットが落ちて通信不能**。宛先側IFの `in` で相手発を拒否し、`out` に静的 `pass` ＋ `dynamic` を置く |
| ⑥ | LAN側インターフェースに `secure filter out` を置く | インターネットやVLAN20からの**戻りパケットまで落ちる**。`lan3/1`・`lan3/3`・`lan1` には `out` を設定しない |
| ⑦ | `ip pp remote address pool` と固定指定IPを併用 | プール側から別アドレスが払い出され**フィルタが効かなくなる**。全ユーザー固定指定・プール未使用 |
| ⑧ | RTX1200/1210の記事どおり `vlan port mapping` を使う | **RTX1300では従来のLAN分割機能が使えない**。`lan flexible-port` で代替（変更時は `save`＋`restart`） |

補足：**フィルタは適用順序が結果を決めます。** 複合機→VLAN20の拒否（2100）は許可（2101）より前、かつ静的に `pass` されないと動的セッションが生成されません。

## 7. リモートアクセスVPN（L2TP/IPsec）

主用途は**社外から自席PCへのRDP／SSH**。L2TPクライアントはVLANに所属しないため、**ユーザーごとに固定IPを払い出しレンジでフィルタを分岐**させて業務系／開発系を分離。

| アカウント | 利用者 | 区分 | 払出IP | 到達範囲 |
|---|---|---|---|---|
| `yohira` | yohira | 業務 | `192.168.201.17` | VLAN10（3389/22） |
| `t.kido` | t.kido | 業務 | `192.168.201.18` | VLAN10（3389/22） |
| `mogik` | mogik | 業務 | `192.168.201.19` | VLAN10（3389/22） |
| `iizuka` | iizuka | 業務 | `192.168.201.20` | VLAN10（3389/22） |
| `yohiradev` | yohira | 開発 | `192.168.201.33` | VLAN20（3389/22） |
| `t.kidodev` | t.kido | 開発 | `192.168.201.34` | VLAN20（3389/22） |

- 利用者4名／アカウント6個。トンネルは**現行踏襲の5本**（同時接続5名まで）
- RDP/SSHの接続先PCは **DHCP予約（`dhcp scope bind`）** で `.100`〜`.149` に固定
- 端末側の確認が必要：**Windowsファイアウォール**のRDP受信規則が「ローカルサブネットのみ」だと `192.168.201.x` から繋がらない。Linuxは `sshd`／firewalld で `192.168.201.0/24` を許可

## 2026-10-19 メンタル休職からの復職者受け入れ方針の相談（結論未確定）

### 相談内容
社内システム・AI・研修採用担当として、メンタル不調による休職からの復職者の受け入れ方針について相談があった。

**現行の運用**
- 復職時は一旦「社内システム担当」に配属する
- ユーザーが「外部プロジェクトでも大丈夫」と判断した場合、外部PJの現場マネージャと相談して配属を決める
- そのまま社内システム担当を継続する場合もある

**問題意識**
- 実際には復職後数ヶ月で退職に至るケースがほとんどになっている
- AIでほぼ作業が自動化され、リハビリ者に与える仕事が実質的に無い
- あえて作業を切り出して任せると、退職時に中途半端な状態を引き取ることになり、場合により一から再検討が必要になる
- そのため「しばらく自習してもらう方が、自分の負担もなく、辞めてもインパクトがない」のではないか

**ユーザーからの問い**: しばらく自習させ、辞めなそうな感じであれば次のステップに進む方が良いか？

### 提示した意見（Claude 側の見解・未承認）
- **「本番の仕事をリハビリの器に使うと中途半端な引き取りが発生する」という問題意識自体は正しい**。AIで「誰がやっても困らない仕事」という緩衝材が消えた構造変化も事実。
- ただし懸念は**自主学習そのものではなく、それが「育成」ではなく「待機・観察の置き場」になる場合**。自主学習（リスキリング）は IT 技術者の中核能力であり業務として正当。危険なのは目標・期限・成果物・フィードバックのない放置状態で、これは離職・再発しやすい条件に近い。**むしろ自主学習を正式な業務として扱い、到達点と成果物を合意すれば、「辞めなそうな感じ」という主観基準を客観的な達成度評価に置き換えられる。**なお「ほとんどが数ヶ月で退職」という結果は、個人の問題ではなく仕組みの出力と見るべき。　※この項目は当初「自習させて様子を見るのは因果が逆」と記載していたが、ユーザー指摘により 2026-10-19 に上記へ差し替え（経緯は後続セクション参照）。
- **労務リスクの指摘**: 復職者に実質的に業務を与えない状態は、意図に関わらず「不利益取扱い」「就労実態のない配置」と評価されるリスクがあり、安全配慮義務の観点でも不利。人事との事前合意が必要。
- **対案は「投資を止める」ではなく「切り離す」**。①本当に役立つ ②クリティカルパスに乗らない ③途中で止まっても捨てられる ④成果が見える、の4条件を満たす仕事の在庫を事前に用意する。具体例として、AI出力の評価・evalデータセット作成（自動化が進むほど「検証する人」が希少になる）、研修教材・新人向けドキュメント、社内ナレッジ／手順書整備、ログ分析、データクレンジング。
- **移行判断は「辞めなそうな感じ」という主観基準をやめ、期間と基準を本人・人事・産業医と文書で合意する**（例: 1ヶ月目＝勤怠安定、2-3ヶ月目＝納期のある小さい仕事1つ、以降＝外部PJ適性判断）。
- **外部PJ適性の判断をユーザー一人で背負うのをやめる**。産業医・人事・現場マネージャの合議事項とすべき。
- 退職された方の離職理由のヒアリング記録が残っているか確認を提案。

## 2026-10-19 「自主学習＝リスク」という整理への異論（ユーザー指摘・論点を修正）

### ユーザーからの指摘
前セクションで Claude が書いた「**『自習させて様子を見る』は因果が逆の可能性が高い**」という整理に対し、ユーザーより異論。

> これは、自主学習、いわばリスキリングであり、IT業界ではこれができないと、そもそもやっていけません。これをリスクだと言われるのは心外です。

**ユーザーの立場**: 自主学習（リスキリング）は IT 技術者にとって必須の中核能力であり、これをリスク要因として扱うのは不適切。

### 論点の修正（Claude 側の誤りを認める）
- **「自主学習がリスク」という表現は誤り**。自主学習そのものは正当な業務であり能力要件である、というユーザーの指摘が正しい。
- 懸念すべきだったのは自主学習そのものではなく、**それが「育成手段」ではなく「待機・観察の置き場」として置かれる場合**。両者は外形が同じでも中身が異なる。

| | 構造のあるリスキリング | 待機としての自習 |
|---|---|---|
| 目標 | 到達点が定義されている | なし（様子見） |
| 期限 | ある | 「辞めなそうになるまで」 |
| 成果物 | ある | なし |
| フィードバック | レビュー・面談がある | なし |
| 本人の認識 | 期待されている | 置かれている |

### 指摘を踏まえて強化された方向性
自主学習が中核能力であるなら、**「仕事がないから代わりにやらせておくもの」ではなく、評価対象の業務そのものとして扱うべき**。具体的には:
- 何を習得するのかを本人と合意する
- 期限と到達点を決める
- 成果物を出させ、レビューする
- **その達成度を「次のステップに進めるか」の判断材料にする**

これにより、前セクションで課題とした「辞めなそうな感じ」という主観基準を、**客観的な達成度評価に置き換えられる**。担当者の負担を増やす話ではなく、判断根拠が明確になる分むしろ軽くなる。

### 労務面の訂正
前セクションの「業務を与えないのは不利益取扱いのリスク」という記述を訂正。**育成計画として文書化されたリスキリング期間は正当な業務であり問題ない**。問題となるのは計画も記録もない放置状態のみ。この点でも「構造を与える」方が安全側に振れる。

### ステータス・残課題
- 前セクション（`## 2026-10-19 メンタル休職からの復職者受け入れ方針の相談`）内の該当記述について、上記の趣旨に沿った**差し替え案を提示しユーザーの承認待ち**。承認が得られ次第修正する。
- 受け入れ方針そのものは引き続き**未確定**。

## 2026-10-19 議論の収束 ——「リスキリング期間を正式な業務として設計する」方向へ

### 収束点
前2セクションのやりとりを経て、ユーザーより「理解した。自分の考え方に一部至らない点があった」との応答。論点が「自主学習か否か」ではなく、**「構造があるか否か」**に整理された。

あわせて確認した点として、当初ユーザーが指摘した **「本番の仕事をリハビリに使うと中途半端な引き取りが発生する」という観察は一貫して妥当**であり、この前提は変わっていない。

### 固まりつつある方針
**リスキリング期間を「仕事がないから代わりにやらせるもの」ではなく、正式な業務として設計する。**

### 具体化にあたり決めるべき4点（未決）
1. **期間**（例: 3ヶ月）と、その間の位置づけ
2. **習得テーマの決め方** — 会社が指定するか、本人と合意するか
3. **成果物の形** — 成果発表／試作／資格／ドキュメント等
4. **次ステップ移行の判定者** — ユーザー単独か、人事・産業医・現場マネージャを含めるか
   - 4 については、担当者が一人で背負わない形にする価値があると Claude から再度提起している

### ステータス・残課題
- 上記4点は**いずれも未決**。たたき台を Claude が作るか、ユーザー自身が整理するかを確認中。

## 2026-10-19 具体化4点は「対象者ごとに都度作成・本人と合意」する運用に決定

### ユーザーの決定
前セクションで挙げた具体化4点（期間／習得テーマの決め方／成果物の形／次ステップ移行の判定者）について、ユーザーより方針決定。

> 具体化にあたり決めるべき4点 は、対象者により変わるものと思います。その都度作成し、本人と合意をとって進めていきます。

**決定内容**: 4点を会社として一律に固定するのではなく、**対象者ごとにその都度作成し、本人と合意した上で進める**。

### Claude から提起した補足（未回答・保留）
1. **「都度作る」と「毎回ゼロから考える」は分けた方がよい**
   - 対象者ごとに変わるのは *中身*（テーマ・期間・成果物）であり、*枠* は共通テンプレート化できる
   - 効果: 毎回ゼロから設計しなくて済む／決め忘れ（特に期限と成果物）を防げる／本人との合意記録がそのまま残る
   - 項目は4つで足りる想定: 習得テーマ／期間と中間確認日／成果物の形／次ステップの判定方法（A4半ページ程度）
2. **4点目（次ステップ移行の判定者）だけは対象者ごとではなく会社の運用として固定すべき**
   - 判定者が対象者ごとに変わると判断が属人化し、**担当者（ユーザー）一人に責任が集中する構造が温存される**
   - これは本人と合意する性質のものでもない
   - 人事・産業医を含む固定の枠組みとして決めておく方が、担当者自身を守ることになる

### ステータス・残課題
- **決定済み**: 4点は対象者ごとに都度作成・本人合意で進める。
- **未決**: 上記 Claude 補足1（テンプレート化の要否）・補足2（判定者を固定運用にするか）への回答待ち。テンプレートのたたき台作成も要否未定。
- **対応済み**: セクション `## 2026-10-19 メンタル休職からの復職者受け入れ方針の相談` 内の「自習させて様子を見るは因果が逆」という記述の差し替えは、**2026-10-19 にユーザー承認を得て対応済み**。
